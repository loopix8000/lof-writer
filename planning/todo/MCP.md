> 작성일: 2026-10-17

## 목적

에이전트가 별도 플러그인 없이 앱의 내장 MCP에 연결하고, Lof의 문서 구조와 저장 규칙에 맞춰 작품·회차·플롯·메모를 관리하게 한다.

요청의 JSON 형식이 유효한 것과, 입력한 데이터가 앱에서 의도한 의미로 쓰이는 것은 별개다. 짧은 작업 지침과 정확한 도구 설명을 제공하고, 서버 검증으로 보완한다.

배경: 가져오기 추적용 `sourceRelativePath`, `sourceSha256`, `sourceHeading`을 사용자 정의 `properties`에 넣어 화면에 노출한 사례가 있었다. 해당 데이터는 정리했으며, 앞으로는 내부 기록과 표시용 속성의 역할을 명확히 안내한다.

## 우선 작업: 연결 시 핵심 지침 제공

- [ ] MCP `initialize` 응답의 `instructions`에 짧은 서버 사용 지침을 포함한다.
- [ ] 현재 지원하는 프로토콜 버전과의 호환을 확인한다.
- [ ] 클라이언트가 지침을 에이전트에 전달하지 않을 가능성을 고려해 도구 설명에도 필수 규칙을 넣는다.
- [ ] 연결 방법을 문서화한다: 앱 실행 → 실행 파일의 `--mcp` 모드로 표준입출력 연결 → 실행 중인 앱으로 요청 전달.
- [ ] 개발 환경의 `scripts/mcp.mjs`는 같은 서버에 연결하는 대체 브리지임을 설명한다.
- [ ] 앱 실행 필요 여부, `runtime.json`의 기본 위치 및 `LOF_RUNTIME` 지정 방법을 안내한다. 실제 인증 토큰을 문서나 로그에 노출하지 않는다.

## 우선 작업: 도구와 필드 설명 보강

- [ ] `project_create`: 먼저 서재를 조회하고 기존 작품의 재사용 또는 신규 생성을 판단하도록 안내한다.
- [ ] `document_create`: 회차·플롯·메모의 구분, `folder`, `episodeId`의 의미를 설명한다.
- [ ] `title`과 `body`: 제목과 본문을 구분하고 원본의 첫 줄을 제목으로 처리하는 조건을 설명한다.
- [ ] `body`: Markdown 입력임을 명시하고 일반 텍스트의 이스케이프·줄바꿈 변환 예시를 제공한다.
- [ ] `manualLineBreak`: 표시와 편집에 미치는 영향을 설명하고 원본 줄바꿈 처리와 함께 안내한다.
- [ ] `properties`: 앱 속성 패널에 표시되는 사용자 정의 YAML 속성임을 명시한다. 내부 추적 정보의 저장 용도로 사용하지 않도록 안내한다.
- [ ] `document_update`·`document_patch`: 최신 `revision` 조회와 `expectedRevision` 사용, 충돌 시 재조회 원칙을 안내한다.
- [ ] `document_reorder`: 회차 순서를 확인·지정하는 절차와 파일 이름 변경에 미치는 영향을 설명한다.
- [ ] `document_read`: 긴 문서의 `offset`·`limit`·`truncated`를 확인해 끝까지 읽는 방법을 설명한다.

## 우선 작업: 서버 입력 검증

- [ ] 공개한 `inputSchema`와 실제 서버의 입력 검증이 일치하는지 점검하고 누락을 보완한다.
- [ ] 필수값·타입·문서 종류·허용 값·본문 크기·경로·참조 대상의 유효성을 검증한다.
- [ ] 문서 수정 시 버전 불일치를 오류로 반환하고 기존 원고를 보존한다.
- [ ] 입력 오류와 저장 충돌을 에이전트가 구분할 수 있게 오류 코드와 설명을 정리한다.
- [ ] 사용자 정의 속성의 자유도는 유지한다. 이번 사례의 키 이름만 전역 금지하거나 화면에서 일괄 숨겨 문제를 덮지 않는다.

## 앱에 포함할 짧은 SKILL.md

- [ ] 에이전트용 `SKILL.md`를 작성하고 앱 배포물에 포함할 위치를 정한다.
- [ ] 특정 AI 제품에만 의존하지 않는 기본 연결 방법과 작업 절차를 담는다.
- [ ] `instructions`·도구 설명·파일 지침의 공통 규칙을 한 곳에서 관리하거나 변경 시 함께 갱신하는 방식을 정한다.
- [ ] 파일의 위치를 에이전트가 찾을 수 있게 안내한다. 파일을 포함하기만 하면 모든 클라이언트가 자동으로 읽는다고 가정하지 않는다.
- [ ] 필요하면 같은 지침을 MCP 리소스로 조회하거나 앱에서 복사·내보내는 기능을 검토한다. 별도 플러그인 설치를 필수로 만들지 않는다.

### 회차 및 자료 가져오기 절차

- [ ] 작업 전 서재와 대상 작품을 조회하여 중복 생성을 피한다.
- [ ] 원본 파일 목록과 숫자 순서를 확인하고, 보관용 복사본과 실제 작업본을 구분한다.
- [ ] 회차와 플롯·메모·후기·백업·통합본의 분류 및 가져오기 범위를 정한다.
- [ ] 첫 줄이 제목인 경우에만 제목과 본문을 분리한다. 본문 첫 문장을 기계적으로 제거하거나 제목을 임의로 교정하지 않는다.
- [ ] 일반 텍스트를 Markdown으로 변환할 때 문장·기호·빈 줄·들여쓰기의 의미를 보존한다.
- [ ] 사용자에게 보여 줄 속성만 `properties`에 넣는다.
- [ ] 원본 경로·해시·원본 제목 등 작업용 정보는 `.lof`의 가져오기 기록 등 별도 관리 영역에 보관한다.
- [ ] 원본 파일은 보존하고, 실패 후 재시도할 때 이미 생성한 문서를 중복 생성하지 않도록 대응 기록을 남긴다.
- [ ] 완료 후 문서 개수·회차 순서·제목·본문을 MCP로 다시 읽어 확인한다. 긴 문서도 전체 범위를 확인한다.
- [ ] 작업 결과에는 실제 등록 범위, 변환 사항, 누락·실패 항목을 구분해 보고한다.

## 후속 검토: 앱이 제공하는 가져오기 기능

- [ ] 에이전트가 매번 자체 변환기를 만들지 않도록 기존 파일 가져오기 기능의 MCP 제공 여부를 검토한다.
- [ ] 제공한다면 원본 추적 기록·변환·분류·재시도 처리를 앱이 담당하도록 입력과 결과를 설계한다.
- [ ] 원본 위치와 사용자 속성을 구분하고, 내부 기록을 원고 속성에 섞지 않는다.
- [ ] 일괄 처리의 부분 실패·재시도·중복 방지 및 결과 목록을 정의한다.

## 완료 판단 기준

- [ ] 연결한 에이전트가 앱 소스를 분석하지 않고도 기본 사용 절차를 파악할 수 있다.
- [ ] 안내에 따라 생성한 문서에는 의도한 사용자 속성만 표시된다.
- [ ] 회차 순서와 문서 분류를 유지하고, 본문이 안내한 변환 범위 외에 바뀌지 않는다.
- [ ] 수정 충돌과 부분 실패가 조용한 덮어쓰기나 중복 생성으로 이어지지 않는다.
- [ ] 안내와 서버가 실제 지원하는 도구·입력·동작이 일치한다.

구현 시 검증은 저장소의 `AGENTS.md` 정책을 따른다. 이 문서 작성 단계에서는 앱 코드 변경이나 테스트 실행을 포함하지 않는다.
