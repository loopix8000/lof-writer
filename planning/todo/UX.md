# 긴 작품의 탐색·집필 화면 UX TODO

> 작성일: 2026-10-17
> 상태: 논의 및 이미지 시안 피드백을 정리한 구현 전 작업 목록.

## 목적과 시안 피드백

회차가 많아졌을 때의 목록 탐색과, 한 회차의 본문이 길어졌을 때의 위치 이동을 함께 개선한다.

- 이미지 시안의 좌측 탐색 구조는 대체로 수용 가능한 방향이다. 세부 동작은 구현 전에 정한다.
- 시안의 우측 영역은 기존 위젯 보드를 충분히 반영하지 못했다. 책갈피 패널로 기존 기능을 대체하지 않는다.
- 최신 방향은 **우측 탭을 없애고, 우측 상단의 책갈피·조판 아이콘으로 필요한 패널을 여는 방식**이다.
- 책갈피 추가는 본문 영역에서 수행한다. 우측에 별도의 책갈피 추가 버튼이나 빠른 실행 버튼 묶음을 두지 않는다.
- **이 회차의 플롯·메모 위젯은 우측에 유지**한다. 좌측 필터로 완전히 대체하는 안은 채택하지 않는다.
- 시안의 **이전 회차 / 다음 회차** 버튼은 도입한다.
- 본문은 일반 파일로 유지하며, 탐색 편의를 위한 화면 구성이 파일 배치나 본문을 임의로 바꾸지 않게 한다.

## 좌측 탐색 영역

- [ ] 상단을 **에피소드 / 문서** 탭으로 분리해 긴 에피소드 목록 아래로 플롯·메모가 밀리지 않게 한다.
- [ ] 회차 번호와 제목으로 즉시 찾을 수 있는 검색을 제공한다.
- [ ] 긴 작품에서는 `1~20화`, `21~40화`, `41~57화` 같은 범위별 접기를 검토한다. 묶음 크기와 적용 기준은 미정이다.
- [ ] 범위 묶음은 화면상의 분류로 처리한다. 이를 위해 실제 원고 파일을 폴더별로 재배치하지 않는다.
- [ ] 최초 표시 시 현재 회차가 있는 묶음을 보여 주고, 이후에는 사용자의 펼침·접힘 상태를 존중한다. 여러 묶음을 함께 열 수 있게 한다.
- [ ] 검색은 접힌 묶음까지 전체에서 수행한다. 검색 해제 시 기존 탐색 위치와 펼침 상태로 돌아갈 수 있게 한다.
- [ ] **현재 회차로 이동** 버튼으로 목록에서 열린 회차를 찾고 표시한다.
- [ ] 목록의 상단 검색·탭·핵심 조작은 긴 목록을 스크롤해도 접근할 수 있게 한다.
- [ ] 새 에피소드 추가를 위해 목록 맨 아래까지 내려갈 필요가 없게 한다.
- [ ] 작품 전환·문서 이동 후 목록의 스크롤 위치와 선택 상태를 적절히 복원한다.
- [ ] 문서 트리에 `전체 문서 / 현재 회차만` 필터를 제공하는 것은 보조 탐색 기능으로 검토한다. 우측의 회차별 플롯·메모 위젯을 없애는 근거로 사용하지 않는다.

## 이전·다음 회차 이동

- [ ] 편집 화면 상단에 **이전 회차 / 현재 위치 / 다음 회차**를 제공한다. 예: `이전 회차 · 42 / 57화 · 다음 회차`.
- [ ] 실제 회차 순서를 기준으로 이동하고 플롯·메모를 회차 순서에 섞지 않는다.
- [ ] 첫 회차의 이전 버튼, 마지막 회차의 다음 버튼은 비활성 상태로 표시한다.
- [ ] 목록 검색이나 접힌 묶음 때문에 이전·다음 이동 대상이 뜻하지 않게 바뀌지 않도록 한다.
- [ ] 기존 문서 이동의 저장·충돌 처리와 연결한다. 저장 실패나 외부 수정 충돌을 무시하고 이동하지 않는다.
- [ ] 이동한 회차의 작업 위치를 복원한다. 항상 본문 맨 위로 초기화하지 않는다.
- [ ] 분할 화면에서 어느 편집 그룹을 이동시키는지 명확히 하고, 포커스가 없는 그룹을 임의로 바꾸지 않는다.

## 우측 영역: 기본 위젯과 책갈피·조판 아이콘

- [ ] 기본 화면은 기존 위젯 보드로 유지한다.
- [ ] 우측 상단에 **책갈피 / 조판** 아이콘을 배치한다. 텍스트 탭이나 큰 버튼 묶음은 두지 않는다.
- [ ] 각 아이콘으로 같은 우측 영역에서 책갈피 목록 또는 조판 설정을 열 수 있게 한다.
- [ ] 기본 위젯으로 돌아오는 조작을 정한다. 같은 아이콘 재선택이나 패널 닫기 등 일관된 동작으로 처리하고 불필요한 버튼을 늘리지 않는다.
- [ ] 아이콘에 툴팁·접근 가능한 이름·활성 상태를 제공해 기능과 현재 열린 패널을 알 수 있게 한다.
- [ ] 우측 영역의 기존 표시·숨기기 조작을 유지하고 패널별 스크롤 상태를 보존하는 범위를 정한다.
- [ ] 패널 전환으로 편집 중인 본문, 커서, 선택 영역, 본문 스크롤이 초기화되지 않게 한다.
- [ ] 패널은 같은 공간을 사용한다. 새 사이드바를 계속 추가해 본문 폭을 과도하게 줄이지 않는다.

### 위젯

- [ ] 현재 위젯 보드의 글자 수·플랫폼별 집계 기능을 유지한다.
- [ ] 이번 회차에서 새로 쓴 글 집계를 유지한다.
- [ ] 현재 회차에 연결된 플롯·메모와 해당 문서로의 이동 기능을 유지한다.
- [ ] 기존 계산 규칙 변경, 연결 문서 조작 등 위젯의 동작이 우측 구조 변경 과정에서 빠지지 않도록 현재 기능을 대조한다.
- [ ] 책갈피 패널이 추가되어도 기존 위젯을 제거하거나 책갈피로 대체하지 않는다.

### 책갈피

- [ ] 현재 문서의 특정 위치에 이름 붙인 책갈피를 만들 수 있게 한다. 예: `여기부터 퇴고`, `대사 확인`, `후반부 연결`.
- [ ] 추가 조작은 본문 문단 옆이나 본문 문맥 메뉴에서 제공한다. 시안의 문단 옆 아이콘을 기본으로 검토하되, 마우스 호버에만 의존하지 않고 키보드로도 접근할 수 있게 한다.
- [ ] 우측에는 책갈피 추가 버튼을 두지 않는다. 우측 상단 책갈피 아이콘을 누르면 목록을 한 번에 볼 수 있게 한다.
- [ ] 책갈피 선택 시 해당 본문 위치로 이동한다.
- [ ] 책갈피 이름 변경·삭제 및 짧은 주변 문맥 표시를 검토한다.
- [ ] 원고 본문에 앱 전용 표식을 삽입하지 않고 별도 관리 정보로 보관한다.
- [ ] 원고 수정으로 위치가 바뀌면 주변 문맥 등을 이용해 재탐색한다. 찾지 못한 책갈피를 엉뚱한 위치로 조용히 연결하지 않는다.
- [ ] 이전 시안의 `목차`는 별도 최상위 탭으로 확정하지 않는다. 소제목·장면 구분선 이동이 필요하면 책갈피 패널 내부 제공 여부를 검토한다.

### 조판

- [ ] 기존 **조판 형식** 설정을 우측 상단 조판 아이콘으로 여는 패널에서 제공하는 범위를 정한다.
- [ ] 기존 설정 화면과 우측 패널이 같은 설정값과 적용 범위를 사용하도록 한다.
- [ ] 에피소드·문서 구분, 기존 기본값 및 설정 저장 방식을 유지한다.
- [ ] 화면 표시를 바꾸는 설정과 실제 원고·복사 결과에 영향을 주는 조판 동작을 구분해 안내한다.
- [ ] 우측 패널로 옮기거나 연결할 항목은 기존 기능을 확인한 뒤 정한다. 시안만 보고 설정을 새로 정의하지 않는다.

## 긴 본문의 위치 이동

- [ ] 문서별 마지막 스크롤·커서 위치를 기억해 다른 문서를 보고 돌아와도 작업을 이어갈 수 있게 한다.
- [ ] 맨 위·맨 아래로 바로 이동하는 조작을 제공한다.
- [ ] 현재 본문 내 위치 표시와 스크롤바의 책갈피 표시를 검토한다.
- [ ] 입력·저장·탭 전환 때 위치가 불필요하게 튀지 않게 한다.
- [ ] 외부 수정 후 위치 복원은 현재 내용에 맞춰 처리하고, 예전 위치로 무조건 이동하지 않는다.
- [ ] 연속 편집을 기본으로 유지한다. 편집 화면의 페이지 분할은 별도 후속 검토로 둔다.

## 구현 전 결정할 세부 사항

- [ ] 좌측 범위 묶음의 크기, 기본 펼침 상태, 작품별 상태 보존 범위.
- [ ] 이전·다음 회차 이동 시 탭 재사용 방식, 보관된 회차의 포함 여부, 회차 종류별 순서.
- [ ] 우측 패널의 전환·복귀 방식과 작품·문서 전환 시 열린 패널 유지 방식.
- [ ] 책갈피의 저장 위치, 외부 수정에 대한 위치 추적 방식, 향후 동기화 범위.
- [ ] 조판 패널과 기존 설정 화면의 역할 분담.
- [ ] 좁은 창·집중 모드·분할 화면에서 각 영역을 표시하는 방식.

## 완료 판단 기준

- [ ] 긴 작품에서도 번호·제목 검색과 현재 회차 찾기로 긴 수동 스크롤을 줄일 수 있다.
- [ ] 문서 영역 접근을 위해 에피소드 전체를 지나갈 필요가 없다.
- [ ] 이전·다음 회차 이동과 작업 위치 복원 중 원고가 유실되거나 저장 충돌이 무시되지 않는다.
- [ ] 기본 위젯과 아이콘으로 여는 책갈피·조판 패널이 의도한 범위대로 동작한다.
- [ ] 회차별 플롯·메모 위젯이 유지되고, 책갈피 추가가 본문에서 자연스럽게 이어진다.
- [ ] 불필요한 탭·기능 버튼을 늘리지 않고 키보드와 마우스로 접근할 수 있다.
- [ ] UI 상태와 책갈피 때문에 일반 Markdown 파일의 독립성이 훼손되지 않는다.

아직 앱 코드는 변경하지 않았다. 향후 구현·검증은 저장소의 `AGENTS.md` 정책을 따른다.
