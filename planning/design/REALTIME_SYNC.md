# Iroh 실시간 파일 동기화

## 범위

- Writer끼리 직접 연결하거나 선택적인 Lof Library 상시 피어에 연결한다.
- 파일 저장소 동기화와 별도로 관리한다. 이전 HTTP/SSE 연결 코드는 제거한다.
- 파일 원본과 기존 파일 비교 엔진의 이름 변경·삭제·충돌 규칙을 재사용한다. 실시간 공동 편집 CRDT나 입력 중인 미저장 본문 전송은 범위에 포함하지 않는다.
- Windows Writer, Windows 데몬 및 명령줄 데몬에 연결한다. Android UI·QR 카메라·백그라운드 서비스는 이 저장소에 없으며 별도 이식 대상이다.

## 공통 전송 계층

`crates/lof-realtime`은 Iroh 1.3.0, ALPN `lof/realtime-files/1`, `presets::N0`를 사용한다. 두 저장소에 같은 소스를 포함하여 각 저장소만으로 빌드할 수 있다. 변경 시 두 복사본을 함께 갱신한다. Rust 1.91 이상이 필요하다.

공식 API: https://docs.rs/iroh/1.3.0/iroh/

각 요청은 QUIC 양방향 스트림 하나를 사용한다. 프레임은 빅엔디언 u32 헤더 크기, UTF-8 JSON `{meta,length}`, 원본 파일 바이트 순서다. 본문 파일은 JSON이나 Base64로 변환하지 않는다. 응답도 같은 형식이며 오류는 `meta.error`에 한국어 문자열을 넣는다. 헤더 8MB, 파일 50MB, 요청 90초, 수신 연결 24개 제한을 둔다.

## 인증과 연결

1. 영구 Ed25519 장치 키를 만든다. Writer는 Windows DPAPI로 암호화해 설정에 보관한다. 데몬은 기존 비공개 관리 DB에 보관한다.
2. 서재별 UUID를 발급한다. 장치 허가는 로컬 서재와 상대 공개키·상대 서재 UUID의 조합에 묶인다.
3. 초대는 `lof-peer://<base64url(JSON)>`이며 `{version:1,addr,vault,token}`을 담는다. 토큰은 무작위 UUID 두 개로 만들며 메모리에만 10분 보관하고 성공 시 소비한다. PC에서는 연결 코드를 붙여 넣어 연결한다. 초대 QR 생성은 제공하되 PC에서 QR을 읽는 화면과 처리기는 제공하지 않는다.
4. `pair` 요청의 공개키는 요청 본문을 믿지 않고 QUIC가 인증한 `remote_id`를 사용한다. 토큰을 상수 시간 비교하고 양쪽 설정을 저장한 뒤 다시 연결한다. 코드가 분실·만료되거나 응답이 끊기면 새 코드를 만든다.
5. 이후 모든 요청은 `vault`(발신 서재)와 `target`(수신 서재)을 전달한다. 연결 해제와 서재 전환 후에도 매 요청에서 허가를 다시 확인한다.
6. `hello`는 연결 확인, `notify`는 변경 알림이다. Writer는 공개키 문자열이 작은 장치가 비교를 수행한다. 데몬은 보관 피어이므로 Writer가 비교한다.

## 파일 교환과 경쟁 처리

`begin`으로 원격 서재의 세션 임대를 얻고 `inventory`, `read`, `exists`, `write`, `remove`, `touch`, `end`를 호출한다. 임대는 180초이며 요청마다 갱신한다. Writer에서는 다른 파일 동기화와 같은 실행 잠금을 사용한다. 연결 종료와 임대 만료 시 해제한다.

`inventory`는 경로별 `{size,modified,etag}`를 반환한다. ETag는 내용의 SHA-256이다. `.lof-sync-id`는 서재 UUID를 반환하는 가상 읽기 전용 항목이며 실제 서재에 쓰지 않는다. 파일 목록은 4만 개까지 허용한다.

각 장치의 마지막 동기화 해시는 로컬 SQLite에 보관한다. 변경된 파일만 교환하며 쓰기·삭제 직전에 이전 내용 해시(`expected`)를 다시 확인한다. 충돌하면 비교를 다시 시도한다. Writer는 기존 원고 이력, 원자적 저장, 휴지통, 메타 정보 복구 사본 처리를 재사용한다. 동시 수정의 주본 선택은 내용 해시로 일치시키고 나머지 원본은 비교한 PC의 `.lof/file-conflicts`에 보관한다.

데몬은 `data/realtime/<서재 UUID>/`에 원본 파일을 보관한다. 덮어쓰기·삭제 전 원본은 그 서재의 `.lof/history/<SHA-256>/<경로>`에 보관한다. 이전 HTTP 서재 DB와 자동으로 변환하거나 합치지 않는다. Library의 백업 명령은 동기화를 중지한 뒤 관리 DB와 원본·이력을 함께 새 폴더에 보관한다.

상대 경로만 허용하고 숨김·관리·임시 파일, 심볼릭 링크, Windows 연결 폴더, 장치 이름, 경로 이탈, 대소문자 충돌을 거부한다. 기기별 DB·이력·설정과 서재 밖의 공용 메모는 전송하지 않는다.

## 변경 감지와 재연결

### 연결 화면의 상태

- 초대의 서버 측 `Instant` 만료 시각을 기준으로 남은 밀리초를 전달한다. UI는 초 단위 타이머와 유효 시간 막대를 표시하고 만료 시 QR과 복사를 비활성화한다. 초대 코드 전체와 QR은 처음 화면을 열거나 초대가 교체될 때만 가져온다.
- 초대 ID별로 코드를 사용한 장치를 기록한다. 새로 보이는 임의의 장치를 완료 대상으로 추측하지 않는다. 같은 장치를 다시 연결한 경우에도 해당 초대의 사용 결과를 표시한다.
- PC는 입력란에 연결 코드를 직접 붙여넣어 연결한다. 형식 검사는 네트워크 없이 실행하며, 코드 원문은 높이 200px의 입력란에 계속 표시한다. 장치 추가를 누르면 코드 생성 탭으로 이동하면서 QR·일회용 코드를 만든다.
- `realtimePair`는 작업 ID를 즉시 반환하고 연결 작업을 진행한다. `realtimeStatus`로 연결 중·실패·완료를 확인하고 `realtimeCancelPair`로 통신 대기를 중단한다. 취소·서재 변경 후에는 로컬 연결 정보를 새로 저장하지 않는다. 이미 완료된 원격 등록을 되돌리는 동작은 아니다.
- 연결 완료 후 로컬 장치 이름을 변경할 수 있다. 첫 동기화는 실제 `lastSync`와 동기화 상태를 사용하며 가상의 진행률·파일 개수를 표시하지 않는다.

### 파일 전송

Writer는 기존 파일 감시 이벤트와 저장 요청으로 전송 세대 번호를 올린다. 5초 작업자는 세대가 바뀐 연결만 비교한다. 원격 `notify`는 작업자를 즉시 깨운다. 변화가 없으면 원고 목록·본문 검사나 앱 수준 동기화 통신을 수행하지 않는다. QUIC 연결 유지와 Iroh 주소 조회·릴레이 통신은 별개다.

데몬은 원본 서재의 파일 감시 이벤트를 모아 5초마다 해당 서재에 허가된 연결에만 알린다. Writer는 연결 시작·재접속 시 전체 목록과 마지막 해시를 비교한다. 실패 시 5~60초로 재시도 간격을 늘리며, 네트워크 복구 후 누락을 맞춘다. 아직 연결한 적이 없는 새 장치는 삭제 이력이 없으므로 최초 연결은 양쪽 파일을 합친다.

## Library 관리

Windows 앱의 서재·기기·코드 발급·다른 기기 연결 메뉴는 모두 같은 Iroh 서재와 피어 권한을 사용한다. 접속 주소·포트·로그인·이전 네트워크 API는 제공하지 않는다. 명령줄 관리는 Windows 명명 파이프 또는 Unix 권한 0600 소켓으로 호스트에서만 접근한다.

Library에서 Writer 또는 다른 Library의 코드를 입력해 연결할 수 있다. `pair` 요청의 `storage:true`로 보관 피어 역할을 전달한다. Writer와의 비교는 Writer가, Library끼리의 비교는 공개키 문자열 순서가 작은 피어가 담당한다. Library는 파일 감시 변경과 재접속에 맞춰 실제 원본 파일을 비교하고 전송한다.

동일한 관리 통신을 사용하는 Docker 명령은 Library 저장소의 README와 API 문서에 정리했다. Library는 원고를 보관하는 피어이며 Iroh 릴레이가 아니다.
