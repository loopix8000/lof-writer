# Lof Writer

**Local First Writing Tool** · 1.0.0-beta.1 (Windows)

로컬 우선 웹소설 집필 도구입니다. 원고는 내 PC에 Markdown 파일로 저장되고, 원할 때만 직접 고른 저장소와 동기화합니다. Tauri 2, React, TypeScript, Tiptap으로 만들었습니다.

## 특징

- **로그인 필요 없음**: 귀찮은 가입, 광고, 구독 없이 실행하면 바로 쓸 수 있습니다.
- **로컬 파일 기반**: 원고는 내 PC의 평범한 Markdown 파일로 저장됩니다. 서버에 올라가지 않고, 다른 편집기로도 열 수 있습니다.
- **동기화 지원**: 원할 때만 직접 고른 저장소(로컬·공유 폴더, FTP/FTPS, WebDAV)로 여러 PC의 원고를 맞출 수 있습니다. 별도 서비스 가입은 필요 없습니다.
- **다중 탭 지원**: 여러 문서를 탭으로 열어 두고 오가며 쓸 수 있고, 화면을 나눠 두 문서를 나란히 볼 수도 있습니다.
- **MCP 지원**: Claude, Codex 같은 AI 도구를 MCP로 연결해 원고를 읽고 검색하고 고치게 할 수 있습니다.

## 실행

`release/win-unpacked/Lof Writer.exe`를 실행합니다. 같은 폴더의 다른 파일도 함께 있어야 합니다.

1. 처음 실행하면 연재 플랫폼이나 사용자 규칙을 고릅니다.
2. `새 프로젝트`로 작품을 만들고 `새 편 쓰기`로 에피소드를 씁니다.
3. 입력을 멈추면 자동 저장됩니다. `Ctrl+S`로 바로 저장할 수도 있습니다.

기본 도서관 위치는 `문서\Lof Library`입니다. 도서관 화면의 `다른 도서관 열기`로 바꿀 수 있습니다.

## 주요 기능

- **작품**: 제목·소개·태그·표지, 에피소드·위키·메모
- **편집**: 기본 서식, Markdown 원문 모드, 따옴표·괄호 자동 닫기, 말줄임표 변환, 집필 상태
- **화면**: 파일 트리·위젯 보드 접기, 탭, 분할 보기, 모바일 미리보기, 집중 모드
- **문서 관리**: 우클릭 메뉴(측면에서 열기·이름 바꾸기·복제·순서 이동·보관·영구 삭제), 보관함, 변경 이력 복원
- **분량**: 플랫폼별 글자 수와 목표 분량, 공백 포함·제외 글자 수
- **검색과 내보내기**: 제목·본문 검색, Markdown/TXT 내보내기, 본문 텍스트 복사
- **가져오기**: `.md`, `.txt`, Muvel 백업(`.mvle`)
- **동기화**: 로컬 폴더, FTP/FTPS, WebDAV
- **연동**: 로컬 HTTP API, MCP

## 글자 수

연재 플랫폼은 노벨피아, 문피아, 네이버 시리즈, 카카오페이지, 사용자 규칙 중에서 고릅니다. 새 작품은 기본 설정을 따르고, 작품마다 바꿀 수 있습니다. 사용자 규칙에서는 공백·줄바꿈 처리, 문장부호·특수문자 제외, 말줄임표 가중치, 목표 분량을 정합니다.

글자 수는 제목과 Markdown 서식을 뺀 본문으로 세고, UTF-16 단위를 씁니다(😀는 2자). 플랫폼별 계산은 공개된 자료를 바탕으로 맞춘 값이라 실제 등록 화면과 조금 다를 수 있습니다.

본문 텍스트 복사와 TXT 내보내기도 같은 본문을 씁니다. 플랫폼에는 서식 없이 `Ctrl+Shift+V`로 붙여 넣으세요.

## 설정

- **편집기**: 글자 크기, 줄 간격, 색 테마(Light Modern, Bakery), 밝게/어둡게, 곡선 따옴표 사용, 자동 닫기, 말줄임표를 포함한 사용자 대치어
- **표지**: PNG/JPEG/WebP 20MB 이하. 큰 이미지는 1800×2400 안으로 줄여 PNG로 저장합니다.
- **태그**: Enter나 쉼표로 추가하며, 최대 30개, 태그당 40자입니다.

## 파일 구조와 백업

```text
Lof Library/
  001 작품명/
    project.json               # 작품 전체 설정
    project.backup.json        # 작품 설정 복구용 사본
    assets/cover-<hash>.png    # 표지
    episodes/001 회차명.md      # 회차 속성과 본문
    doc/                       # 플롯·메모 Markdown과 사용자 폴더
  .lof/
    vault.json
    index.json                 # 재생성 가능한 문서 메타데이터·검색·정렬 캐시
    search/<작품 ID>/          # 문서별 본문 검색 캐시
    history/<문서 ID>/         # 속성을 포함한 Markdown 변경 이력
    drafts/<문서 ID>.json      # 저장 전 임시 원고
    imports/<가져오기 ID>/     # 가져온 원본 파일과 변환 보고서
    recovery/                  # 구조 이관 전 작품 정보와 원본 Markdown
    sync/                      # 저장소별 동기화 기준점
    project-conflicts/         # 동기화 충돌 때 보관한 원격 작품 정보
    deleted.json               # 영구 삭제한 문서 기록
```

회차·플롯·메모의 개별 속성은 각 `.md` 파일 상단의 YAML 프런트매터(`---` 사이)에 저장합니다. 고정 ID, 제목, 상태, 태그, 줄바꿈, 회차 연결, 보관 상태와 회차 순서를 파일과 함께 관리합니다. `lof: 1`은 속성 형식의 표시입니다. 새 문서는 UUID를 사용하고, 기존 문서는 이전 ID를 그대로 파일에 고정해 연결과 이력을 유지합니다. 이름이나 폴더를 바꿔도 ID는 바뀌지 않습니다.

작품 설정은 계속 `project.json`에 둡니다. 회차·플롯·메모 목록은 `episodes/`와 `doc/`의 파일에서 복원할 수 있으며, 별도 등록 목록이 없어도 문서의 YAML ID와 순서를 읽어 구성합니다.

일반 조회는 메모리 색인과 `.lof/index.json` 캐시를 사용합니다. 파일 변경 시 해당 항목만 갱신하고, 본문 검색 캐시도 문서별로 저장합니다. 처음 구성하거나 캐시가 손상·삭제되었을 때 전체 색인을 다시 만듭니다. 재실행 시에는 파일 크기·수정 시각 등을 비교해 변경된 원본만 읽습니다.

```markdown
---
lof: 1
id: "bb5d9364-b39c-4a72-bb1e-e43e8cc93179"
kind: "memo"
title: "인물 메모"
tags:
  - "주인공"
manualLineBreak: false
episodeId: null
archived: false
---
여기부터 본문입니다.
```

속성은 편집기 본문·글자 수·본문 검색·본문 복사·TXT 내보내기에서 제외합니다. Markdown 내보내기에는 속성이 포함되고 다시 가져올 때도 읽습니다. YAML 문서 트리를 수정하므로 변경하지 않은 항목의 주석·키 순서·인용 표기와 사용자 정의 속성을 보존합니다. 잘못된 YAML은 원본을 덮어쓰지 않고 오류로 표시합니다.

변경 이력은 제목·본문과 태그·줄바꿈·회차 연결 등 속성을 함께 보관하고 복원합니다. 예전 JSON 이력도 계속 읽을 수 있습니다. 이력에서 사라진 회차의 연결을 복원할 때는 독립 문서로 복원합니다.

이전 `project.json` 문서 속성·순서는 열 때 자동 이관합니다. 이관 전에 `.lof/recovery/`에 작품 정보와 변경 대상 Markdown 원본을 백업하며, 본문 줄바꿈과 빈 줄은 그대로 유지합니다. 기존 ID와 연결·이력도 유지합니다.

도서관 폴더를 통째로 복사하면 원고, 설정, 변경 이력이 함께 백업됩니다. 원고는 암호화하지 않습니다. 저장소 비밀번호는 Windows safeStorage로 암호화해 앱 설정에 보관합니다.

영구 삭제한 문서 파일은 Windows 휴지통으로 가고, 변경 이력과 임시 원고는 지워집니다.

## 동기화

설정 → 외부 저장소에서 연결을 추가하고 `동기화`를 누릅니다. 각 장치는 원격의 `lof-writer-sync-v1` 폴더에 자기 도서관 스냅샷을 올리고, 다른 장치의 스냅샷을 받아 합칩니다. 함께 쓸 장치에서는 같은 원격 폴더를 지정하세요.

- **로컬 폴더**: 같은 PC의 다른 폴더나 공유 폴더
- **FTP/FTPS**: 호스트, 포트, 계정, 원격 폴더. FTPS는 명시적 TLS입니다. SFTP는 지원하지 않습니다.
- **WebDAV**: WebDAV 주소, 계정, 원격 폴더

같은 문서를 두 장치에서 고치면 한쪽을 `(동기화 충돌 사본)`으로 남깁니다. 작품 정보가 충돌하면 로컬 정보를 유지하고, 원격 정보는 `.lof/project-conflicts`에 보관합니다.

영구 삭제는 다른 장치에도 전달됩니다. 다만 그 장치에서 마지막 동기화 이후 고친 문서는 지우지 않습니다.

동기화는 직접 눌러서 실행하며, 장치당 50MB, 최대 100대까지입니다. 변경 이력, 가져온 원본, 비밀번호, 편집기 설정은 동기화하지 않습니다.

## MCP / API

설정의 `MCP 설정 복사`로 받은 JSON을 MCP 클라이언트에 등록하면, 실행 중인 앱과 같은 저장 로직으로 원고를 다룰 수 있습니다. 앱 폴더를 옮겼다면 다시 복사해 등록하세요.

제공 도구: `library_list`, `document_read`, `document_search`, `project_create`, `document_create`, `document_update`, `document_patch`, `history_list`, `history_read`, `history_restore`

- 수정할 때는 `document_read`로 받은 `revision`을 `expectedRevision`으로 보냅니다.
- `document_patch`는 본문에서 정확히 한 번 나오는 문자열만 바꿉니다.
- 긴 문서는 `document_read`의 `offset`과 `limit`로 나눠 읽을 수 있습니다.

API는 `127.0.0.1`에서만 열리고, 실행할 때마다 포트와 인증 키가 바뀝니다. 브라우저에서 온 요청은 거절합니다. 설정의 `API 연결 정보 복사`로 주소와 키를 확인하고, `POST /rpc`로 호출합니다.

```json
{ "name": "document_read", "arguments": { "id": "문서 ID" } }
```

`Authorization: Bearer <키>`와 `Content-Type: application/json` 헤더가 필요합니다. 같은 포트의 `/mcp`로 HTTP MCP도 쓸 수 있지만, 표준 입출력 연결을 권장합니다. 앱 설정 폴더의 `runtime.json`에는 인증 키가 들어 있으니 공유하지 마세요.

## 알려진 제한

- Windows PC 버전만 있습니다.
- 표, 이미지, HTML, 링크가 들어간 문서는 원문 모드로 엽니다.
- 자동 저장 직전에 PC가 강제로 꺼지면 마지막 입력이 사라질 수 있습니다.
- 같은 문서를 다른 프로그램과 동시에 편집하지 마세요.
- FTP와 WebDAV는 실제 NAS·서버 환경에서 충분히 검증하지 않았습니다.
- 코드 서명을 하지 않은 알파 버전입니다.

## 개발

Node.js 24 이상에서:

```powershell
npm ci
npm run build
npm start
npm test
npm run smoke
npm run smoke:edge
npm run smoke:features
npm run smoke:navigation
npm run smoke:chrome
npm run package        # 폴더 배포본
npm run package:msi    # MSI 설치 파일
```

서명된 MSI 업데이트 빌드와 GitHub 초안 릴리즈 설정은 [RELEASING.md](RELEASING.md)를 참고하세요. 업데이트 주소와 공개키를 설정하기 전에는 앱이 업데이트 서버에 연결하지 않습니다.

개발 서버를 쓸 때는 한 PowerShell 창에서 `npm run dev`를 실행하고, 다른 창에서 `$env:LOF_DEV_URL='http://127.0.0.1:5173'; npm start`를 실행합니다. 테스트는 임시 폴더만 쓰므로 실제 원고에 영향이 없습니다.

MSI의 UpgradeCode는 고정값이라 이후 버전에서도 바꾸면 안 됩니다. MSI 버전 번호는 `0.2.0-alpha.N`을 `0.2.N`으로 바꿔 씁니다.
