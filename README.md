## 특징

- **로그인 필요 없음**: 귀찮은 가입, 광고, 구독 없이 실행하면 바로 쓸 수 있습니다.
- **로컬 파일 기반**: 원고는 내 PC의 평범한 Markdown 파일로 저장됩니다. 서버에 올라가지 않고, 다른 편집기로도 열 수 있습니다.
- **동기화 지원**: 연결해 둔 저장소(로컬·공유 폴더, FTP/FTPS, WebDAV)에 원고 변경을 자동으로 동기화합니다.
- **다중 탭 지원**: 여러 문서를 탭으로 열어 두고 오가며 쓸 수 있고, 화면을 나눠 두 문서를 나란히 볼 수도 있습니다.
- **MCP 지원**: Claude, Codex 같은 AI 도구를 MCP로 연결해 원고를 읽고 검색하고 고치게 할 수 있습니다.

## 주요 기능

- **작품 관리**: 작품 소개·태그·표지, 에피소드·위키·메모, 문서 보관과 변경 이력 복원
- **사용자 속성**: 아이콘·속성명·값을 직접 만들고 Markdown YAML에 저장합니다. 설정 → 기본 설정에서 속성 프리셋과 자주 쓰는 태그를 관리할 수 있습니다.
- **집필**: 기본 서식, Markdown 원문 모드, 따옴표·괄호 자동 닫기, 말줄임표와 사용자 대치어
- **화면 구성**: 다중 탭, 두 문서를 나란히 보는 분할 화면, 모바일 미리보기, 집중 모드
- **분량 확인**: 플랫폼별 글자 수, 공백 포함·제외 글자 수, 목표 분량
- **검색과 내보내기**: 제목·본문 검색, Markdown/TXT 내보내기, 본문 텍스트 복사
- **가져오기**: Markdown(`.md`), 텍스트(`.txt`), Muvel 백업(`.mvle`)
- **꾸미기**: 글자 크기·줄 간격, 색 테마(Light Modern, Bakery), 밝게·어둡게 설정
- **외부 연동**: 여러 PC 간 동기화, AI 도구 연결용 MCP와 로컬 API
- **트레이**: 창을 닫으면 트레이로 숨깁니다. 트레이 아이콘을 클릭하면 다시 열리고, 우클릭 메뉴의 ‘종료’로 앱을 완전히 종료합니다.

## 실시간 동기화

왼쪽 사이드바 아래 **구름 아이콘**에서 현재 서재를 **동기화 그룹**에 연결합니다. 창 왼쪽 탭에서 **동기화 그룹**, **초대 코드 만들기**, **그룹 가입**을 선택합니다. 그룹에 속한 장치 하나의 **초대 코드 만들기** 탭에서 페어링 코드를 복사한 뒤 새 장치의 **그룹 가입** 탭에 붙여 넣으세요. 그룹이 없는 서재에서 코드를 만들면 그 서재로 새 그룹을 만듭니다. 코드는 10분 동안 한 번만 사용할 수 있으며, 생성한 QR은 다른 장치에 보여 줄 수 있습니다. 한 그룹에는 장치를 최대 10대까지 연결할 수 있습니다. 가입 전에 양쪽에서 동기화할 서재를 열어 주세요.

페어링 코드를 한 번 입력해 가입하면 그룹의 나머지 장치를 자동으로 찾아 연결합니다. 이후 새 장치가 추가되거나 제거되면 기존 장치에도 자동으로 반영됩니다. 처음 가입할 때는 코드를 만든 장치가 켜져 있어야 하지만, 그 뒤에는 그룹을 만든 장치가 꺼져 있어도 나머지 장치끼리 동기화합니다. 모든 장치를 껐다 켜도 저장한 그룹 구성원 정보로 다시 연결합니다.

초대 화면에는 남은 시간이 `분:초`로 표시됩니다. 만료되면 복사가 비활성화되고 **새 코드 만들기**로 다시 발급할 수 있습니다. 긴 코드는 **페어링 코드 직접 보기**를 펼쳤을 때만 표시합니다. 새 장치가 가입하면 완료 화면으로 전환합니다.

**동기화 그룹** 탭에서 **장치 초대**를 누르면 QR·페어링 코드가 바로 생성됩니다. 새 PC에서는 **그룹 가입** 탭의 입력란에 코드를 붙여넣고 **가입하기**를 선택하세요. 형식이 올바른 코드를 입력해야 버튼이 활성화됩니다. 이미 다른 장치가 있는 그룹에 속한 서재는 **그룹 나가기**를 한 뒤에 다른 그룹에 가입할 수 있습니다. 가입 중에는 취소할 수 있고, 실패하면 같은 화면에서 코드를 바꾸거나 다시 시도합니다. 가입이 끝나면 실제 첫 동기화 상태를 확인하고 **이름 변경**으로 이 PC에서 보이는 장치 이름을 바꿀 수 있습니다.

이전 버전의 1:1 장치 연결은 이 버전으로 업데이트할 때 한 번 초기화됩니다. 모든 장치를 업데이트한 뒤 한 장치에서 코드를 만들어 나머지 장치를 같은 그룹에 다시 가입시켜 주세요. 다시 가입한 뒤 첫 동기화는 양쪽 파일을 합치며 삭제를 전달하지 않습니다.

그룹의 장치는 서재의 원본 파일을 읽고 수정할 수 있습니다. Markdown·작품 정보·이미지·첨부 파일의 변경을 감지해 5초 단위로 전송하며, 상대 변경 알림을 받거나 다시 연결하면 빠진 내용을 비교합니다. 변경이 없을 때에는 원고 검사와 동기화 요청을 반복하지 않습니다. 전송 연결 유지와 재접속은 네트워크 계층에서 처리합니다.

Iroh 1.3.0의 암호화된 QUIC와 기본 `N0` 설정을 사용합니다. 직접 연결을 우선 시도하고 필요하면 공용 릴레이를 이용합니다. Lof Library는 파일을 보관하는 선택적인 상시 피어입니다. 두 PC만으로도 사용할 수 있습니다.

양쪽 수정이 겹친 사본은 비교를 수행한 PC의 `.lof/file-conflicts`에 보관합니다. 열려 있는 원고는 **바뀐 내용 불러오기**로 반영합니다. 서재 밖에 따로 지정한 공용 메모와 기기별 DB·이력·설정은 공유하지 않습니다. 장치를 그룹에서 제거하거나 그룹에서 나가도 이미 전달된 파일은 각 장치에 남습니다.

현재 연결 화면은 데스크톱용입니다. Android의 QR 스캔·수명 주기 연동은 Android 앱에서 별도로 구현해야 합니다.

## 파일 동기화

> **동기화는 아직 불안정할 수 있습니다. 중요한 원고는 별도로 백업해 주세요.** 동기화하려면 사용하는 모든 기기의 Lof Writer를 최신 버전으로 업데이트해야 합니다. 구버전 앱은 새 동기화 데이터를 받을 수 없습니다.

설정 → 파일 동기화에서 **로컬 폴더, FTP/FTPS, WebDAV**를 연결할 수 있습니다. Google Drive 직접 연동은 제거했으며, 기존 Google Drive 연결은 목록과 동기화 대상에서 제외됩니다. Drive의 원격 파일은 삭제하지 않습니다.

앱 시작과 트레이에서 열 때, 설정한 자동 동기화 주기마다 저장소의 변경을 확인하고 받기·충돌 확인·보내기를 처리합니다. 기본 주기는 1분이며 설정에서 1분부터 1시간까지 선택할 수 있습니다. 자동 저장된 변경은 다음 주기에 모아서 전송하고, 원고를 수동 저장하거나 각 저장소의 **동기화** 버튼을 누르면 바로 실행합니다. 트레이에서도 계속 동작하며, 실패한 연결은 재시도 대기 후 다시 확인합니다. 상태는 집필 화면의 폴더 동기화 아이콘과 설정 → 파일 동기화에 표시합니다. 외부 편집기의 파일 변경은 OS 알림으로 감지하고, 열린 본문은 사용자가 안내줄의 ‘바뀐 내용 불러오기’를 눌렀을 때 반영합니다.

연결한 저장소의 `lof-writer-files-v1` 폴더에 **서재의 폴더 구조와 파일 원본**을 유지합니다. Markdown 본문과 YAML 속성, 작품별 `project.json`, 이미지·첨부 파일을 바이너리 변환이나 본문 JSON 변환 없이 주고받습니다. SQLite DB, 기기별 수정 이력, 잠금·임시 파일, 복구용 `project.backup.json`은 전송하지 않습니다. 서재 밖에 별도로 지정한 공용 메모 경로도 대상에 포함하지 않습니다.

마지막 동기화 내용과 비교해 변경·추가·삭제를 양방향으로 반영합니다. 양쪽에서 수정한 파일은 충돌 처리 설정을 따르며, **충돌 사본 보관**을 선택한 경우 한쪽 원본을 서재의 `.lof/file-conflicts/<내용 해시>/<원래 경로>`에 보관합니다. 삭제와 편집이 겹치면 편집한 원본을 보존합니다. 저장소의 파일을 다른 편집기로 수정한 내용도 가져올 수 있습니다.

이 방식으로 전환하는 첫 실행에서 기존 폴더·WebDAV·FTP/FTPS 연결을 한 번 초기화하고, 기존 사용자에게 재연결 안내를 표시합니다. 원고와 원격 파일은 삭제하지 않습니다. **설정 → 파일 동기화에서 저장소를 다시 연결해 주세요.** 재연결한 뒤에는 연결 설정을 유지합니다. 구형 `lof-writer-sync-v1` 저장소는 연결별 첫 동기화 때 읽어서 가져오며, 이후 새 파일은 원본 파일 규격으로만 전송합니다. 함께 쓰는 모든 PC를 업데이트해 주세요.

## 로컬 수정 이력

원고는 기존 Markdown 파일로 유지하고, 색인과 수정 이력은 각 기기의 `.lof/library.sqlite`에 보관합니다. 외부 편집이나 동기화로 교체되는 원고도 이 기기가 관찰한 이전 내용을 남깁니다. 이력은 하루 한 번 문서당 최근 100개·30일을 기준으로 정리하며 최소 10개를 보존합니다. 설정의 **로컬 이력 백업**으로 실행 중에도 일관된 SQLite 백업을 만들 수 있습니다.

외부 편집으로 본문이나 속성이 달라지면 파일의 실제 수정 시각을 DB에 기록하고 동기화의 `updatedAt`에 반영합니다. 원고 파일의 속성은 다시 쓰지 않습니다. 변경 직후 1초 이내이거나 읽는 도중 파일 상태가 바뀌면 이력 기록과 동기화를 보류하고 다시 확인합니다. 앱에서 저장하거나 동기화로 받은 문서는 해당 문서의 수정 시각을 유지합니다.

열린 원고에 외부 변경 안내가 표시된 상태에서 문서나 앱 창을 닫으면 외부 파일의 최신 내용을 사용하고 이전 임시 원고를 정리합니다. 내 편집을 남기려면 닫기 전에 **내 편집 사본 만들기**를 선택하세요.

기존 서재를 처음 열면 관리 파일과 이력을 사본으로 보존한 뒤 SQLite로 이관합니다. 원고 파일은 이관 때문에 재작성하지 않습니다.

## PIN 잠금

설정 → 앱 잠금에서 4~12자리 숫자 PIN을 등록할 수 있습니다. 등록하면 앱 시작과 트레이에서 다시 열 때 PIN을 확인합니다. 최소화 후 복원할 때는 다시 묻지 않으며, PIN 변경·해제에는 현재 PIN이 필요합니다. 5회 잘못 입력하면 30초 동안 재입력을 제한합니다.

앱 화면을 잠그는 편의 기능으로, 로컬 원고 암호화나 MCP / API 접근 제한은 제공하지 않습니다. PIN은 원문 대신 무작위 솔트와 PBKDF2 해시로 저장합니다. PIN을 잊었다면 앱을 완전히 종료한 뒤 기본 설정 경로인 `%APPDATA%\Lof Writer\pin.json`을 삭제해 초기화할 수 있습니다. `LOF_USER_DATA`를 지정했다면 해당 폴더의 `pin.json`을 사용합니다.

## 주의사항

- Windows PC용이며, 코드 서명은 되어 있지 않습니다.
- 메모·플롯에서는 마크다운 표를 직접 편집할 수 있습니다. 이미지·HTML·링크가 들어간 문서와 에피소드의 표는 원문 모드로 엽니다.
- 자동 저장 전에 PC가 강제로 꺼지면 마지막 입력이 사라질 수 있습니다.
- 같은 문서를 다른 프로그램과 동시에 편집하지 마세요.
- 글자 수는 실제 연재 플랫폼의 등록 화면과 차이가 있을 수 있습니다.
- FTP와 WebDAV는 실제 NAS·서버 환경에서 충분히 검증하지 않았습니다.

## 개발 정보

Tauri 2, Rust, React, TypeScript, Tiptap을 사용합니다.

Node.js 24 이상과 Rust, Tauri 2용 Windows 빌드 환경이 필요합니다.

```powershell
npm ci
npm start
```

프론트엔드 빌드는 `npm run build`, Rust 빌드 검사는 `src-tauri` 폴더에서 `cargo check`로 실행합니다.

Windows 배포본 빌드는 `npm run package`, MSI 생성은 `npm run package:msi`를 사용합니다. 릴리즈와 업데이트 설정은 [RELEASING.md](RELEASING.md)를 참고하세요.
