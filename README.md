## 특징

- **로그인 필요 없음**: 귀찮은 가입, 광고, 구독 없이 실행하면 바로 쓸 수 있습니다.
- **로컬 파일 기반**: 원고는 내 PC의 평범한 Markdown 파일로 저장됩니다. 서버에 올라가지 않고, 다른 편집기로도 열 수 있습니다.
- **동기화 지원**: 연결해 둔 저장소(로컬·공유 폴더, FTP/FTPS, WebDAV)에 원고 변경을 자동으로 동기화합니다.
- **다중 탭 지원**: 여러 문서를 탭으로 열어 두고 오가며 쓸 수 있고, 화면을 나눠 두 문서를 나란히 볼 수도 있습니다.
- **MCP 지원**: Claude, Codex 같은 AI 도구를 MCP로 연결해 원고를 읽고 검색하고 고치게 할 수 있습니다.

## 주요 기능

- **작품 관리**: 작품 소개·태그·표지, 에피소드·위키·메모, 문서 보관과 변경 이력 복원
- **사용자 속성**: 아이콘·속성명·값을 직접 만들고 Markdown YAML에 저장합니다. 설정 → 기본 설정에서 속성 프리셋과 자주 쓰는 태그를 관리할 수 있습니다.
- **집필**: 기본 서식, Markdown 원문 모드, 따옴표·괄호 자동 닫기, 말줄임표와 사용자 대치어
- **화면 구성**: 다중 탭, 두 문서를 나란히 보는 분할 화면, 모바일 미리보기, 집중 모드
- **분량 확인**: 플랫폼별 글자 수, 공백 포함·제외 글자 수, 목표 분량
- **검색과 내보내기**: 제목·본문 검색, Markdown/TXT 내보내기, 본문 텍스트 복사
- **가져오기**: Markdown(`.md`), 텍스트(`.txt`), Muvel 백업(`.mvle`)
- **꾸미기**: 글자 크기·줄 간격, 색 테마(Light Modern, Bakery), 밝게·어둡게 설정
- **외부 연동**: 여러 PC 간 동기화, AI 도구 연결용 MCP와 로컬 API
- **트레이**: 창을 닫으면 트레이로 숨깁니다. 트레이 아이콘을 클릭하면 다시 열리고, 우클릭 메뉴의 ‘종료’로 앱을 완전히 종료합니다.

## 파일 동기화

> **동기화는 아직 불안정할 수 있습니다. 중요한 원고는 별도로 백업해 주세요.** 동기화하려면 사용하는 모든 기기의 Lof Writer를 최신 버전으로 업데이트해야 합니다. 구버전 앱은 새 동기화 데이터를 받을 수 없습니다.

설정 → 파일 동기화에서 **로컬 폴더, FTP/FTPS, WebDAV**를 연결할 수 있습니다. Google Drive 직접 연동은 제거했으며, 기존 Google Drive 연결은 목록과 동기화 대상에서 제외됩니다. Drive의 원격 파일은 삭제하지 않습니다.

앱 시작과 트레이에서 열 때, 설정한 자동 동기화 주기마다 저장소의 변경을 확인하고 받기·충돌 확인·보내기를 처리합니다. 기본 주기는 1분이며 설정에서 1분부터 1시간까지 선택할 수 있습니다. 자동 저장된 변경은 다음 주기에 모아서 전송하고, 원고를 수동 저장하거나 각 저장소의 **동기화** 버튼을 누르면 바로 실행합니다. 트레이에서도 계속 동작하며, 실패한 연결은 재시도 대기 후 다시 확인합니다. 상태는 집필 화면의 폴더 동기화 아이콘과 설정 → 파일 동기화에 표시합니다. 외부 편집기의 파일 변경은 OS 알림으로 감지하고, 열린 본문은 사용자가 안내줄의 ‘바뀐 내용 불러오기’를 눌렀을 때 반영합니다.

동기화 데이터는 연결한 저장소의 `lof-writer-sync-v1` 폴더에 기기별 색인과 문서별 최신 JSON 파일로 저장됩니다. 처음에는 현재 문서를 모두 올리고, 이후에는 바뀐 문서만 주고받습니다. 수정 이력과 SQLite DB는 동기화하지 않습니다. 구형 스냅샷은 읽을 수 있지만 새 변경은 v2 규격으로 저장하므로, 함께 쓰는 모든 PC를 업데이트해 주세요.

## 로컬 수정 이력

원고는 기존 Markdown 파일로 유지하고, 색인과 수정 이력은 각 기기의 `.lof/library.sqlite`에 보관합니다. 외부 편집이나 동기화로 교체되는 원고도 이 기기가 관찰한 이전 내용을 남깁니다. 이력은 하루 한 번 문서당 최근 100개·30일을 기준으로 정리하며 최소 10개를 보존합니다. 설정의 **로컬 이력 백업**으로 실행 중에도 일관된 SQLite 백업을 만들 수 있습니다.

기존 서재를 처음 열면 관리 파일과 이력을 사본으로 보존한 뒤 SQLite로 이관합니다. 원고 파일은 이관 때문에 재작성하지 않습니다. 자세한 저장 구조와 복구 범위는 [저장·이력·동기화 설계](planning/design/STORAGE_SYNC.md)에 정리했습니다.

## PIN 잠금

설정 → 앱 잠금에서 4~12자리 숫자 PIN을 등록할 수 있습니다. 등록하면 앱 시작과 트레이에서 다시 열 때 PIN을 확인합니다. 최소화 후 복원할 때는 다시 묻지 않으며, PIN 변경·해제에는 현재 PIN이 필요합니다. 5회 잘못 입력하면 30초 동안 재입력을 제한합니다.

앱 화면을 잠그는 편의 기능으로, 로컬 원고 암호화나 MCP / API 접근 제한은 제공하지 않습니다. PIN은 원문 대신 무작위 솔트와 PBKDF2 해시로 저장합니다. PIN을 잊었다면 앱을 완전히 종료한 뒤 기본 설정 경로인 `%APPDATA%\Lof Writer\pin.json`을 삭제해 초기화할 수 있습니다. `LOF_USER_DATA`를 지정했다면 해당 폴더의 `pin.json`을 사용합니다.

## 주의사항

- Windows PC용이며, 코드 서명은 되어 있지 않습니다.
- 메모·플롯에서는 마크다운 표를 직접 편집할 수 있습니다. 이미지·HTML·링크가 들어간 문서와 에피소드의 표는 원문 모드로 엽니다.
- 자동 저장 전에 PC가 강제로 꺼지면 마지막 입력이 사라질 수 있습니다.
- 같은 문서를 다른 프로그램과 동시에 편집하지 마세요.
- 글자 수는 실제 연재 플랫폼의 등록 화면과 차이가 있을 수 있습니다.
- FTP와 WebDAV는 실제 NAS·서버 환경에서 충분히 검증하지 않았습니다.

## 개발 정보

Tauri 2, Rust, React, TypeScript, Tiptap을 사용합니다.

Node.js 24 이상과 Rust, Tauri 2용 Windows 빌드 환경이 필요합니다.

```powershell
npm ci
npm start
```

프론트엔드 빌드는 `npm run build`, Rust 빌드 검사는 `src-tauri` 폴더에서 `cargo check`로 실행합니다.

Windows 배포본 빌드는 `npm run package`, MSI 생성은 `npm run package:msi`를 사용합니다. 릴리즈와 업데이트 설정은 [RELEASING.md](RELEASING.md)를 참고하세요.
